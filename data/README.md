# `data/` — dataset workspace

This directory holds the floor-plan corpus and derived artifacts. **Everything under `data/` except this README is gitignored** — see root `.gitignore`.

## Expected layout

```
data/
  raw/                       # source images, organized by source/typology
    <source>/                # e.g. developer_acme, partner_xyz
      <typology>/            # nha_ong | nha_pho | biet_thu | chung_cu | nha_cap_4 | khac
        plan_001.png
        plan_001.meta.json   # optional metadata override
  manifest.jsonl             # generated by `python -m dataset ingest`
  splits/
    train.jsonl
    val.jsonl
    test.jsonl
  models/                    # trained CV checkpoints (do not commit)
```

## Provisioning

For local development, point `data/raw` at a small sample (10–20 plans) you have rights to. The CV training scripts will be configured to read from `data/`.

For team / CI access to the full corpus: use object storage (S3 / Cloudflare R2) with read-only access keys distributed out of band. Sync with:

```bash
# Example — replace with your actual bucket
aws s3 sync s3://phongthuy-dataset/raw/ data/raw/ --no-progress
```

## What goes here vs in git

| Lives in git                                        | Lives in `data/` (gitignored)       |
|-----------------------------------------------------|-------------------------------------|
| Ontology YAML (`packages/ontology/.../data/*.yaml`) | Floor plan images (binary)          |
| Schema and labeling guide                           | Generated manifests                 |
| Code                                                | Train/val/test splits               |
|                                                     | Model checkpoints                   |

Annotations themselves: live in the manifest (JSONL), which lives under `data/`. Sync them via the same object-storage bucket.
